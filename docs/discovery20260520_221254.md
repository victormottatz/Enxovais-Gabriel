# Discovery Notes - LionIDE
**Data:** 2026-05-20
**Pipeline:** Development 2.0

---

## Visao

### Problema
Desenvolvedores que trabalham com agentes de IA para desenvolvimento enfrentam dois problemas opostos:

1. **IDEs como Cursor/Windsurf**: editores visuais bonitos com agente IA, mas toda customizacao avancada (subagentes, regras, skills) exige editar arquivos .md escondidos em pastas de config (ex: `.cursor/rules/`), sem nenhuma interface visual.

2. **Claude Code**: agente poderoso, mas roda no terminal — texto correndo, sem editor visual, sem painel de gestao, sem botoes.

O LionIDE resolve isso sendo um ambiente de desenvolvimento completo (fork do VS Code) onde toda customizacao do agente vira interface grafica nativa: criar subagentes por formulario visual, skills em grid clicavel, integracoes (MCP servers) via OAuth com um clique. O agente principal roda sobre o Claude Code e entende automaticamente o contexto do projeto.

Resumo: "Claude Code com interface grafica de IDE completa, onde configurar agentes e clicar em vez de editar arquivo".

### Usuario principal
**Perfil primario:** Desenvolvedor brasileiro junior a pleno (1-5 anos de experiencia) aprendendo a trabalhar com agentes de IA de forma estruturada. Ja usou ChatGPT ou Cursor, mas nunca configurou um agente especializado com tools customizadas. Trabalha principalmente com projetos web (Next.js, Python/FastAPI) ou automacoes.

**Dia a dia:** Abre a IDE de manha com uma feature pra entregar. Quer pedir pro agente "implementa o login seguindo o padrao do projeto" e que ele entenda o codebase, leia os arquivos certos, escreva no estilo certo, rode os testes e commite. Prefere clicar em "Novo Agente", escolher o modelo, marcar quais ferramentas o agente pode usar, escrever o prompt de papel do agente, salvar e usar — sem editar arquivos de configuracao escondidos.

Quando quer reaproveitar logica entre projetos (ex: "todo agente meu deve gerar componentes React nesse padrao"), cria uma skill pela interface e ativa quando precisar.

**Nao e:** dev senior de big tech que vive no terminal Linux. E quem quer produtividade alta com agente IA sem precisar aprender 200 conceitos de CLI antes. Quer ver acontecendo, clicar, entender o que cada agente esta fazendo.

**Perfil secundario:** Criadores de conteudo sobre IA e devs que demonstram workflows de agente em videos/cursos. A interface visual facilita mostrar o que esta acontecendo na tela.

### Referencia
**Base de referencia:** Cursor (cursor.com) — fork do VS Code com agente IA embutido (Composer) no painel lateral. Editor Monaco, terminal integrado, file tree, git. O agente conversa, edita arquivos, executa comandos. LionIDE replica essa base solida.

**Segunda referencia:** Antigravity (Google) — outro fork do VS Code com agente baseado em Gemini. Valida a viabilidade de forkar o VS Code e plugar agentes diferentes.

**Diferenciais do LionIDE (nenhum desses tem com interface nativa):**
1. **Gerenciamento visual de subagentes** — agentes especializados que o agente principal pode invocar. No Cursor nao existe. No Claude Code e arquivo .md.
2. **Gerenciamento visual de skills** — habilidades reutilizaveis que ensinam o agente a fazer algo especifico (ex: "criar PDFs", "gerar slides PowerPoint"). Hoje sao arquivos de texto em pastas escondidas.
3. **Gerenciamento visual de MCP servers** — Model Context Protocol (padrao Anthropic) para conectar agentes a servicos externos (Gmail, Notion, Stripe, etc.). Cursor tem suporte a MCP, mas a configuracao e JSON manual.

### Pitch
LionIDE e um ambiente de desenvolvimento completo — fork do VS Code — com o poder do Claude Code integrado e uma interface grafica nativa para gestao de agentes de IA. Enquanto Cursor e Windsurf escondem a customizacao de agentes em arquivos de configuracao, o LionIDE permite criar subagentes especializados, skills reutilizaveis e conectar MCP servers (integracoes externas como Gmail, Notion, Stripe) com cliques — sem editar JSON ou Markdown. Feito para o desenvolvedor brasileiro jr/pleno que quer trabalhar com agentes de forma seria e produtiva, sem precisar dominar a linha de comando. (Pitch validado pelo usuario)

## Funcionalidades

### Core features

**1. Chat com agente principal no painel lateral**
O usuario abre uma pasta no LionIDE (igual VS Code), o painel lateral direito exibe o chat do agente. O agente entende automaticamente o projeto aberto: le estrutura de arquivos, identifica o framework, edita arquivos, executa comandos no terminal integrado (rodar testes, instalar dependencias), commita via git se solicitado.
Quando a tarefa e complexa, o agente principal invoca subagentes especializados. O painel mostra a hierarquia em tempo real (arvore de tarefas): "Agente Coder esta implementando o endpoint, Agente Reviewer vai validar quando terminar."

**2. Gerenciamento visual de subagentes e skills**
- "Novo Agente": formulario com campos: nome, icone, modelo de IA (Claude Sonnet 4.6 / Opus 4.7 / Haiku 4.5 / modelo local via URL customizada), tools permitidas (checkboxes: Ler Arquivo, Escrever Arquivo, Editar Arquivo, Executar Bash, Buscar Padrao, Buscar Web, etc.), prompt do sistema (textarea), nivel de esforco (baixo/medio/alto), modo de raciocinio (ligado/desligado/adaptativo).
- "Nova Skill": nome, descricao, prompt da habilidade, tools necessarias, categoria (Design, Documentos, Ferramentas, etc.). Skills aparecem em grid agrupado por categoria com toggle on/off.
- Tudo salvo em banco SQLite local no app, sem servidor externo.

**3. Conexao de MCP servers via interface clicavel**
Tela dedicada lista MCP servers disponiveis (Gmail, Google Drive, Notion, Supabase, Stripe, etc.). Cada item mostra: nome, status (Conectado/Precisa Autenticar), origem, versao, numero de ferramentas expostas. Botao "+ Novo Server" para adicionar customizado. Servidores OAuth abrem fluxo nativo de autenticacao. Toggle por projeto para ativar/desativar MCPs especificos por contexto.

### Integracoes
**Modelo BYOK (Bring Your Own Key):** o usuario cola sua propria chave de API Anthropic nas configuracoes do Claude Code (ou autentica via login Anthropic). O LionIDE herda essa autenticacao automaticamente — sem servidor intermediario do LionIDE. As chamadas vao direto da maquina do usuario para a Anthropic.

**Claude Code (motor do agente):** ferramenta oficial de agente da Anthropic. E o motor do agente principal. O LionIDE invoca o Claude Code passando o path do workspace aberto e renderiza a saida na UI grafica.

## Tecnico

### Stack
**Base:** Fork do VS Code (TypeScript + Electron, licenca MIT). Clone do repositorio oficial com rebranding (nome, icones, splash screen, About page).

**Motor do agente:** Claude Code via **Anthropic Agent SDK** (biblioteca Python oficial da Anthropic). O LionIDE invoca o motor passando o path do workspace, captura a saida e renderiza na UI (chat, arvore de tarefas, eventos de subagentes). Herda autenticacao, sessao, MCPs e path-awareness nativamente.

**Interface customizada:** pasta `src/vs/workbench/contrib/lion/` com componentes React para o painel lateral Lion (chat, lista de subagentes, grid de skills, lista de MCPs). Isolamento em pasta propria para facilitar manutencao em merges futuros com upstream.

**Persistencia local:** SQLite via `better-sqlite3`. Armazena agentes, skills, MCPs configurados, historico de conversa, configuracoes de projeto. Sem servidor externo.

**Protocolo MCP:** mesmo padrao Model Context Protocol do Claude Code. Integracoes herdadas automaticamente da configuracao do Claude Code do usuario; LionIDE adiciona UI visual para gerenciar.

**Build e distribuicao:** `electron-builder` gerando `.dmg` (macOS), `.exe` (Windows), `.AppImage` (Linux). Certificados de assinatura para Mac e Windows ja disponíveis.

**Manutencao:** sync trimestral com upstream microsoft/vscode (1 dia a cada 3 meses para merge, resolucao de conflitos e rebuild).

### Plataforma
Exclusivamente desktop — app Electron. Sem versao web ou mobile.

### Notas adicionais

**1. Path-awareness e obrigatorio**
O agente principal deve herdar o comportamento de "estar no diretorio do projeto" automaticamente, identico ao Claude Code CLI quando rodado dentro de uma pasta (`claude` no terminal). Ao abrir uma pasta no LionIDE, o agente ja sabe o caminho do workspace, consegue ler arquivos, executar comandos relativos aquela pasta e entender a estrutura do codigo. Sem isso o produto nao tem razao de existir.

**2. Workspace = projeto independente**
Cada pasta aberta e um workspace com conjunto proprio de subagentes/skills/MCPs ativos. Configuracoes em dois lugares:
- **Por projeto:** `.lion/config.json` na raiz do projeto (versionavel no git junto com o codigo)
- **Globais:** `~/.lion/` no home do usuario (valem para todos os projetos)

**3. Branding completo e consistente**
- Nome "LionIDE" em todo lugar, logo do leao laranja, splash screen customizado, About page reescrito, icone do dock customizado
- Sem nenhuma mencao visivel ao VS Code na UI do usuario
- Licenca MIT do VS Code mantida no LICENSE.txt (obrigacao legal), mas a UI nao exibe "Visual Studio Code"

**4. Distribuicao inicial controlada**
- Build assinada digitalmente, distribuida via download direto no site da comunidade do proprietario
- Exclusiva para membros pagantes nos primeiros 60 dias
- Apos 60 dias: liberacao de versao Community gratuita para qualquer pessoa baixar

**5. Sync com upstream — compromisso assumido**
Merge trimestral com `microsoft/vscode` (branch principal). Estrategia: isolar customizacoes em `src/vs/workbench/contrib/lion/` para minimizar conflitos. Sem esse ciclo, em 1 ano o fork perde extensoes novas, correcoes de seguranca do Electron e merge vira impossivel.
